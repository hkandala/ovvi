title: "Files and Git"
description: "Browse, read and edit files with File Explorer, and see, stage, commit and push changes with Git."
---

Ovvi comes with two plugins that show a folder in a pane card. A plugin is a small web app that Ovvi shows in a card.

- File Explorer shows a folder as a tree. It opens a file as a text editor, a Markdown page or a preview.
- Git shows a repository. It lists the changes, commits them, and shows the history and the diff of a change or a
  commit.

Both work on This Mac and on remote machines. Ovvi installs them the first time it starts. They update apart from
the app, and you can edit them as you edit any plugin ([Plugins](/docs/plugins)).

## Open a File Explorer or Git card

You can open File Explorer or Git in these ways:

1. Make a new pane, then pick File Explorer or Git in the list ([New pane](/docs/guide/basics#new-pane)).
2. Choose File ▸ Open File Explorer Here or File ▸ Open Git Here. The card's own menu and the command palette have
   the same commands. The pane you are in changes into the new card.
3. In the command palette, choose Open File… and type a path, Open Working Tree, or Open Commit… and type a hash.
4. ⌘-click a path in a terminal ([Links and paths](/docs/guide/navigate#links-and-paths)).

Open File Explorer Here and Open Git Here open the root of the git repository that holds the pane's folder. Outside a
repository, they open the pane's folder.

Agents can open these cards too, with the `ovvi` command ([The ovvi command](/docs/reference/ovvi-command)).

## Open links and files

A file, a folder, a commit or a link opens as in every card ([Links and paths](/docs/guide/navigate#links-and-paths)).
A click opens it in the same card, as its next place. These cards differ in three ways:

- In the tree, a double-click opens a row.
- On a folder, the right-click menu has Open as Root.
- A file from a Git diff always opens in a new tab or to the side, because File Explorer shows it.

## Back and Forward

Each card has Back and Forward buttons at the left of its second row. They move through the places that the card
showed, as a browser does. Press ⌃- for Back and ⌃⇧- for Forward. ⌘← and ⌘→ also work, except in a text field.

The card keeps its last five places. When you go back to one of them, it shows at once, as you left it: its scroll,
its open folders, its selection and its filter.

If a file has unsaved edits, Back, Forward, a new place in the card or a close asks first. The card shows "‹name› has
unsaved edits." with Discard and Keep Editing.

## File Explorer

![A File Explorer card with the tree beside a Markdown file](/images/file-explorer.png)

### The tree

The tree shows the files and folders of the root folder. A folder lists its contents when you open it. Git's status
letters show next to changed files, and a folder shows a dot when a file inside it changed.

The second row of the card has these controls:

- Back and Forward.
- The root. This is the folder path. Click it, type a new path and press Return to go there. A relative path starts
  from the current root, so `src` and `..` work. Press Esc to put the old path back.
- Choose Folder…, the folder icon before the path. It opens a folder picker.
- Filter. It opens the find bar.
- Collapse All. It closes every open folder.
- Show Hidden Files, the eye. It shows the names that start with a dot. View ▸ Show Hidden Files (⇧⌘.) does the same.

The first row of the tree is `..`. Double-click it to make the parent folder the root. Double-click a folder to make
it the root. Click its arrow to open it in place.

Use the keys as in a Finder list:

| Key | Does |
|---|---|
| ↑ ↓ | Moves the selection |
| → ← | Opens and closes a folder |
| Return | Renames the selected file or folder. Press Return to save, Esc to cancel. |
| ⌘O or ⌘↓ | Opens the selected row: a folder becomes the root, a file shows in the card |
| ⌘↑ | Makes the parent folder the root |
| A letter | Opens the find bar with that letter |

The right-click menu also has Rename.

### Filter the tree

Press ⌘F, click Filter, or start to type in the tree. The find bar shows at the top right. It matches file names
anywhere under the root and shows them with their folders open. In a repository, it ignores the files that git
ignores. Press Return or ↓ to move to the matches. Press Esc to close the bar and clear the filter.

### The status bar

A line at the bottom of the tree shows the counts of the root, for example "3 folders, 12 files · 2 hidden". On a
remote machine, the machine's name shows first.

If the root is in a git repository, the right side shows:

- The branch.
- The lines added and removed since the last commit.
- Pull and Push, each with a count, when there is something to pull or push.
- Fetch.
- Git, which opens the Git card for the repository in a new tab.

### A file

A text file opens in an editor with line numbers, syntax colors and undo. The second row shows the path of the file
as breadcrumbs. Click a folder in the breadcrumbs to go back to the tree with the file selected.

- Word Wrap wraps long lines. The card keeps the choice for every file it shows.
- File Tree shows the tree beside the file, in the same card. Drag its edge to make it wider. Press ⇧⌘E (View ▸
  Switch Between Tree and File) to move the keyboard between the file and the tree. While the tree shows, ⇧⌘. (View ▸
  Show Hidden Files) shows and hides its hidden files.
- Open in Browser shows on an HTML file on This Mac. It opens the page in a browser card in a new tab.
- Open With, at the right end, opens the file in its default Mac app. Its menu lists the other apps and plugins that
  open the file.

To find text, press ⌘F. The find bar has Match Case, Whole Word and Regular Expression. Press Return or ⌘G for the
next match and ⇧Return or ⇧⌘G for the previous one. To replace text, press ⌥⌘F (Edit ▸ Find and Replace…).

### Save a file

A dot after the card's title shows that the file has unsaved edits. Press ⌘S to save.

If the file changes on disk while the card shows it:

- With no edits, the card loads the new text. The caret and the scroll stay.
- With edits, the card asks. Reload takes the new text from disk. Keep Mine keeps your text.

If the file changed on disk after you opened it, ⌘S asks first, with Overwrite and Reload. If a save fails, the card
says why, with Try Again.

### Markdown

A Markdown file opens as a page. The second row has three controls:

- Rich Text or Source. Rich Text shows the page as it reads. Source shows the Markdown text, with the page beside it.
  Click Hide Preview on the divider to hide the page.
- Read or Edit. Read locks the file. Edit lets you change it. In Rich Text, the line with the caret shows its
  Markdown. Press ⌘E (View ▸ Lock Editing) to switch.
- Outline. It shows the headings at the left. Click one to go to it.

Click a task box to tick it. When the file is locked, Ovvi saves the change at once.

A relative link opens the file in the card. A web link opens a browser card in a new tab.

### Preview

Images, PDF files, audio and video open in a preview. For images and PDF files, the second row has Zoom to Fit, Actual
Size, Zoom Out and Zoom In. A PDF also shows its page number. A file that Ovvi cannot show displays its icon, kind and
size.

## Git

![A Git card with its changes, the message field and the history graph](/images/git.png)

### The Git home

The Git card opens on its home page. The second row has:

- Back and Forward.
- The branch menu. Pick a branch to switch to it. Remote branches with no local branch are under Remote.
- Working Tree. It opens the diff of all changes that are not committed.
- Fetch, Pull and Push. Pull and Push show how many commits you are behind and ahead.

Below the row are the commit message and the lists of changes.

### Stage and commit

The Staged Changes and Changes lists show each changed file with its status letter. Move the pointer over a file to
see its buttons:

- Stage or Unstage moves the file between the two lists.
- Revert puts the file back as it is in the last commit. Ovvi asks first. A new file is deleted.

Each list has Stage All or Unstage All and Revert All in its header. Click a file to open its diff.

To commit:

1. Type a message in the Message field.
2. Click Commit, or press ⌘↩.

If no change is staged, the button reads Commit All. It stages every change, then commits.

If the folder is not in a repository, the page says "Not a Git repository" and shows Initialize Repository.

### History

Under the changes, the history shows the commits of every branch and tag as a graph, newest first. Each commit shows
its branches, its subject, its author, its short hash and its age. Click the short hash to copy the full hash.

- Click a commit to select it. Double-click it or press Return to open its diff.
- ↑ and ↓ move the selection.
- Show More, at the end, loads more commits.

### Diffs

A diff shows each changed file in a box with its lines added and removed. The Working Tree diff is live: it changes
as you or an agent edit files. A commit's diff starts with its subject, message, author, date and parents. Click a
parent to open its diff.

The second row has:

- File List. It shows the changed files at the left. Click one to go to it.
- Git Home. It goes back to the home page.
- Unified or Side by Side.
- Word Wrap.
- Previous Change and Next Change.

Each file's header has Viewed, which folds the file, and Open File, which opens it in File Explorer. ⌘-click a line
to open the file at that line.

Use these keys in a diff:

| Key | Does |
|---|---|
| ] and [ | Next change and previous change. ⌘G and ⇧⌘G do the same. |
| `}` and `{` (⇧] and ⇧[) | Next file and previous file |
| ⌘F | Opens a filter of the files by path |

## Settings

Each plugin has a page in Settings ▸ Plugins ([Plugin settings](/docs/plugins/install#plugin-settings)). A setting is
the starting value for a new card. A card keeps its own choice after you change it in its header.

| Plugin | Setting | What it changes |
|---|---|---|
| File Explorer | Show hidden files | Shows the names that start with a dot in a new tree |
| File Explorer | Dim ignored and hidden files | Dims the files that git ignores and the hidden files in every tree |
| File Explorer | When a file opens | Show only the file, or Show the file with the tree |
| File Explorer | Markdown opens in | Rich Text or Source |
| File Explorer | Lock Markdown for reading | Opens Markdown locked (Read) or unlocked (Edit) |
| Git | Diff layout | Unified or Side by Side for a new diff |
| Git | Wrap long lines | Word Wrap in a new diff |
| Git | Show the file list when a diff opens | Opens a diff with the file list |
| Git | Commits in the history | How many commits the history loads at first, and Show More adds |

Each plugin page also has Show in New Pane. Turn it off to remove the plugin from the new pane list.

## On a remote machine

File Explorer and Git work the same on a remote machine, with these differences:

- Open With shows no Mac apps, because the file is not on this Mac. ⌘⌥-click shows a notice for the same reason.
- Open in Browser does not show.
- Choose Folder… asks you to type a path.
- A file larger than 4 MB opens read only.
- The cards see a change on disk after a short delay.
- Git uses the git and the credentials of the remote machine. If it has no git, the cards show no git status. An SSH
  key with a passphrase and no SSH agent makes Pull and Push fail.
