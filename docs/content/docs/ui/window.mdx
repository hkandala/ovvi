## Windows

- Each window shows one machine
  ([What a machine is](/docs/machines#what-a-machine-is)). File ▸ New Window
  (⌘N) opens another window (D34) that connects to nothing by itself: it shows
  "Open a Session" over a glass list (the Open Session panel's, 420 pt wide):
  one group per machine, This Mac first, each with its running then its
  stopped sessions ("Running", "Stopped"), a spinner row while the machine
  answers. Each machine reads on its own and answers within 15 s, whatever
  the others do; then its row says "No answer within 15 s". A machine with no
  session lists `default`; one whose sessions cannot be read lists `default`
  with why and its symbol (no herdr: a box; a remote machine that is not
  connected, needs a password or does not answer: `network.slash`; This Mac's
  other errors: a warning triangle). A pick opens that
  session as the window's first page; on This Mac a stopped one starts. A
  window that macOS restores before its pick shows the list again. A run
  with `-session` lists only `ovvi-*` sessions. Two windows can show different
  machines or the same machine.
- Two windows on the same machine share the live data of each session. Each
  window keeps its own selection: page, space, tab, keyboard card, zoom
  and sidebar width.
- A new window opens in the middle of the screen at 90 % of its size, at
  least 1200 × 760 pt and at most the screen's size. A window macOS restores
  keeps its frame. Zooming the window (⌥-click on the green button) fills the
  screen.
- Control is per session (D66). When two windows show the same session, the
  window where the user last typed or clicked in a terminal controls that
  session's panes. The other window watches: its cards dim a little and a
  [control capsule](#control-capsule) offers **Take Back**. Two windows on
  different sessions each control their own session.

## Title row

One row, 46 pt tall as in Rex, always the same (D45). While the sidebar is
open, the traffic lights, the sidebar toggle and the machine button sit in a
leading area as wide as the sidebar, so the first tab starts where the cards
start, also during a resize. From left to right:
1. The traffic lights, centered on the row at 23, 46 and 69 pt from the
   left, where Rex has them. The window has no toolbar: `TrafficLights`
   moves the three standard buttons onto the 46 pt row with plain frame
   changes, again after every AppKit layout; full screen has none. (An empty
   toolbar's accessibility frame covered the title row on a Mac with a notch.) The row's
   items start 91 pt in, so the sidebar toggle sits where Rex has it.
2. The sidebar toggle, always shown outside the overview (⌃⌘S). It has no highlight when the
   sidebar is open. The icon changes instead: an outline window with a sidebar
   line while the sidebar is closed (`sidebar.left`), and the sidebar part
   filled while it is open (`sidebar.left` under
   `rectangle.leftthird.inset.filled`). The sidebar slides in and out over
   0.3 s, and does not slide under Reduce Motion. Each window keeps its own
   choice. Items in the row are 8 pt apart.
3. The [machine button](#machine-button).
4. The [space button](#space-button), only while the sidebar is
   collapsed.
5. The [tab bar](#tab-bar): the selected space's tabs, whether the sidebar
   is open or collapsed.
6. A spacer.
7. The [overview](#overview) button (⌃⌘O).
8. ⌘ (the command palette, ⌘K) and `+` (new tab, ⌘T).

While the overview is open the row shows only the traffic lights and one ×
that leaves it ([Overview](#overview)).

Each title-row button shows the system tooltip with
the action's name and its shortcut, for example "New Tab ⌘T". So do the page
header's `+`, the footer's Open Session button and each card header button.

The window title is "‹tab title› - ‹page title›" (the page in view's sidebar title: the machine's name for
`default`), so the
Window menu and Mission Control show it.

## Machine button

- The machine's icon alone: no chevron and no name. This Mac is a
  laptop when it has an internal battery, else a desktop.
- The menu lists the machines, each with its icon and name, and a checkmark
  on the current one. Then "Open Session…" (the window's Open Session panel,
  as ⌥⌘T, for the machine's other sessions), "Add Remote Host…" and, with
  remote machines in the list, "Edit Remote Host ▸" with each of them
  ([Add a machine](/docs/ui/add-a-machine)).
- Picking another machine brings its window forward (the one used last, when
  there are several); with none open, a new window on it opens with its
  `default` session. This window and its pages stay. Picking the window's own machine
  does nothing.
- macOS 27 draws no images in these menu rows, so there only the names show.

## Space button

Shown only while the sidebar is collapsed, after the machine button.
- An outline folder icon, then "‹page title› | ‹space›" (the sidebar page header's title, so the
  machine's name for `default`): the title in the
  title row's chrome color, a thin vertical line in the divider color, the
  space in the selected title color, a step brighter, all semibold. Then
  a chevron. At most 260 pt wide: the session name stops at 110 pt (with an
  ellipsis), and a space name that does not fit fades out at its end over
  16 pt.
- The menu starts with a filter field ("Filter or create…"). Then one group
  per page open in this window, in page order, under the session's name. A
  row shows the space's state icon (the state label's symbol, a gray
  ring for an idle agent, a quiet dot without an agent), its name and its
  branch on the right.
  At the end, under the list and always in view: New Space, then "Open
  Session…" (⌥⌘T).
- The menu is a glass panel under the button, 300 pt wide, its space list
  at most 340 pt tall (then it scrolls), built from the palette's filter list. Rows are 26 pt. The arrows
  or the pointer move the highlight, Enter acts, Esc closes. A typed name that matches no space shows
  "New Space “‹name›”" first; Enter makes it in the session of the page
  in view and selects it.
- Picking a space of another page also shows that page.

## Tab bar

The tab bar is always in the title row. The sidebar never lists tabs (D45).
One capsule per herdr tab of the selected space (D42).
- **Track.** A capsule 34 pt tall sits behind the tabs. It is hidden when the
  space has one tab; Classic dark has none, as in Rex.
- **Width.** Every tab is 220 pt wide and never shrinks. When the tabs do not
  fit, the bar scrolls sideways (a scroll gesture over it), and a 24 pt fade
  shows on each end that has tabs out of view. A click selects a tab where it
  is, with no scroll; a tab selected another way (keys, the palette, a new tab)
  comes into view at once, without motion. A tab or a pane dragged and held
  near either end of the bar scrolls it (the scroll view's own drop scroll).
  The bar makes only the capsules in and near its view, so a space with
  many tabs shows as fast as one with a few.
- **New tabs.** ⌘T, `+` and a pane dropped on `+` or the bar's empty end
  make a new tab at the end of the space's tabs, as in Safari. An open
  from a card (⌘-click, Open in New Tab, Git's Open File), a link opened in a
  new tab, the palette's Open File, Open Working Tree and Open Commit, and
  `ovvi open --tab` make it right after the card's tab (the keyboard card's
  for the palette, the asking pane's for `ovvi open`); Archived's Resume
  right after the space's selected tab. herdr adds every tab last, and the app then
  moves it (`tab.move`). The bar shows the tab in its place from its first
  frame, never at the end first: the app keeps it there until herdr's order
  matches, or for at most two snapshots after herdr's answer to the move.
- **Dividers.** 1 pt wide, 18 pt tall, centered between
  tabs. A divider next to the selected or the hovered tab is hidden, at once.
- **Selection.** One marker sits on the selected tab. It is 30 pt tall and
  fully round, 2 pt inside the track, as in Rex. Every switch (a click, +,
  ⌘T, ⌘1…⌘9, ⇧⌘[ and ⇧⌘], ⌃⇥, the palette, a close, an open from a card, the
  overview) shows the tab's page at once, and the marker jumps with it: no
  slide, no fade. A new tab or a closed tab changes the bar at once too: no
  pill grows, shrinks or glides. A sideways swipe never changes the tab
  ([Swiping](/docs/ui/swiping)). Glass draws the marker as a Liquid Glass
  capsule, Classic as a plain raised pill.
- **Close.** When the selected tab closes, the window selects the tab used
  before it (the latest one still open), else the tab on its left, else the
  new first tab.
- **Hover.** The hovered tab gets the hover fill over 0.14 s, the same shape
  as the selection; the whole 34 pt slot takes the clicks.
- **Content.** The program icons (11 pt in from the track's edge), the title
  (10 pt after them; the selected tab's in white 0.9 or black 0.9, the others
  in the title row's chrome color), and one status slot. A tab with
  several panes shows its panes' icons overlapping: up to 5, 4 pt apart, the
  keyboard card's icon in front. A tab with one pane shows one icon
  ([Program icons](/docs/ui/program-icons)).
- **Title.** One line. When it does not fit, its end fades out over 16 pt; it
  never shows an ellipsis. The folder part is in secondary text. The title is
  herdr's tab label. When the label is herdr's default (only digits), the
  title is the keyboard card's program and its folder's name, for example
  "zsh ~" or "pi ovvi" (D65). An agent's tab shows the agent's name and its
  pane's name in secondary text ("Claude Code Fix login"), a browser's
  "Browser" and its page, and a plugin's name and title ("File Explorer ovvi"). Until the program is known (a new tab's first
  second), the title is "New Tab", never the number.
- **Plain-text titles.** Where a title is plain text, with no dimmed part, a
  ` | ` separates its two parts: "zsh | ovvi", "Claude Code | Fix login",
  "Browser | Hacker News". That is in ⌘K, the Window menu, Move Pane to Tab,
  the window title, a close dialog, the floating window's title and the
  accessibility labels built from them. The tab capsule, the hover card and
  the overview keep the dimmed part.
- **Status slot.** Pin Tab (`pin`; Unpin Tab, `pin.slash`, on a pinned tab) and × only on the hovered tab: two 22
  pt hit areas, 2 pt apart, over the capsule's end, so the tab's width never changes; the title then fades out
  before them, never under them. A pinned tab shows in the sidebar's [Pinned](#pinned). Otherwise the state icon (12 pt) of the tab's
  strongest agent, centered where the × shows, on every tab with an agent that
  is not idle, the selected one too; the title fades out before it too. The
  icon never moves. An idle agent shows nothing
  ([Theme and accessibility](/docs/ui/theme-and-accessibility#status)).
  VoiceOver reads the state in the tab's value: "codex, needs you".
- **Announcement.** When a tab that is not selected turns to needs you or
  finished, its icons bounce once (1 → 1.15 → 1, a spring) and its title shows
  "‹agent› needs you" or "‹agent› finished" for 3 s. A long text fades at its
  end like any title. Reduce Motion turns the bounce off.
- **Context menu** on a capsule: Rename Tab, Pin Tab (Unpin Tab on a pinned tab), Move Tab Left, Move Tab Right,
  Close Tab, Close Other Tabs, Close Tabs to the Right. The last two are also in
  the File menu and the palette, for the selected tab. Each asks once, with
  what runs and the total pane count, only when a program besides the shell
  runs in one of the panes. Rename (or a double-click anywhere on the capsule) puts a
  text field in place of the title: Enter saves, Esc cancels.
- **Keycap hints.** If the user holds ⌘ for 0.7 s while the window is key,
  each of the first nine capsules shows a keycap "⌘1"… at its end, where the
  state icon sits, or left of the pin while hovered; the title fades out before
  it, and never runs under it. The space rows show theirs at the same
  time. The keycaps fade in over 0.13 s and out over 0.1 s when ⌘ is released.
- Drag a capsule to reorder the tabs ([Drag and drop](/docs/ui/drag-and-drop)).
- Rest the pointer on a capsule to see the [hover card](#hover-card).

## Sidebar

Flat on the window background, with no panel (D44). Arc-style pages, one per
session open in this window (D43). One view (D111): from top to bottom the page header, [Pinned](#pinned) (sticky),
the [space rows](#space-rows) with their [agents](#agent-rows) (the only part that scrolls),
[Archived Sessions](#archived-sessions) (sticky) and the footer.
- **Open sessions, not all sessions.** A window starts with one page: the
  machine's `default` session, started if it is stopped. It never loads the
  other sessions by itself. The user adds pages with
  [Open Session](#open-session), as many as they like. Only open pages have a
  `HostStore`, snapshot reads and an event stream.
- **Detach Session.** The context menu of the page header
  has Detach Session (also in the File menu). It removes the page from this
  window. Its store disconnects, so its event stream and its terminal streams
  end. The herdr session keeps running and stays in the Open Session list.
  Detach Session is disabled on the last page. The UI says "session", never
  "page": Window ▸ Previous Session and Next Session show the page before or
  after.
- **Restore.** Windows come back after a normal quit too: Ovvi registers
  `NSQuitAlwaysKeepsWindows` in its own defaults, so the system's "Close
  windows when quitting an application" setting does not apply to it (a
  user's own `defaults write` still wins). A window that macOS restores opens
  the pages it had again,
  each with its selected space and tabs. A session that no longer runs is
  skipped, and a space or tab that is gone falls back to herdr's focus. A
  window never comes back in full screen: one that macOS restores in full
  screen leaves it. A new window (⌘N) opens with no page, for the user to pick
  one ([Windows](#windows)).
- **Pages.** A sideways swipe on the sidebar moves to the next or previous
  open page ([Swiping](/docs/ui/swiping)); so do ⌥⌘[ ], and ⌥⌘1–9 show a page by its place (Window menu). There
  are no page dots: the page header names the page in view.
- **Page header.** The session's name, the page's title (13 pt bold, the
  rows' size, primary); for a machine's `default`
  session, the machine's name instead: This Mac's own name (System Settings,
  "Hari's MacBook Pro") or the remote machine's name from the list. The Open
  Session panel and the palette keep the real names. Its text starts where
  everything under it starts: 18 pt in from the window's edge, on the
  space rows' names and branch lines, the pinned tabs' and agents' icons and the shelf's label. It
  sits 3 pt above the first
  row, and, at the trailing
  end, a `+` that makes a new space in that session, in `$HOME`. The
  snapshot after it selects the new space.
- **Middle.** The [space rows](#space-rows), 6 pt apart. 18 pt fades show at the top and
  bottom of the space list when content is under them. When the selected space
  changes, however it changes (a click, the overview, ⌃⌘[ ], ⌃⌘1–9, a
  ⌥ + swipe, the palette, a notification), the list scrolls just
  enough to show its row, clear of the fade, without motion.
- **Empty session.** A session with no space shows the compact empty state on its page
  ([States](/docs/ui/states)): `square.dashed`, "No Spaces" and a New Space button. The window's content shows no button, only an icon and
  "This session is empty".
- **Footer.** The filter field and one button, **Open Session** (⌥⌘T), which
  opens the [Open Session](#open-session) panel. The filter keeps the rows
  whose name or branch matches, and the rows with an agent whose name, agent, space or tab matches, unfolded to
  those agents (a row kept by its branch alone stays folded). A matching worktree also keeps its repository's row.
  With none, the compact empty state says "No matching spaces" (`magnifyingglass`). It also filters Pinned (by the tab's title or its space's name) and
  Archived Sessions. The footer has no New Space and no Add Remote Host:
  the page header has `+`, and the machine menu has Add Remote Host.
- **Width.** 300 pt in a new window, from the window's edge to the cards: the rows sit 10 pt in from the window's
  edge, and the 8 pt handle lies over the gap before the cards. Drag the
  handle to resize it between 227 and 480 pt. Each window keeps its own
  width, also after a relaunch.

The sidebar shows tabs only in Pinned, and its bottom never shows agent activity.

## Pinned

The page's pinned tabs, on top of the sidebar under the page header; they never scroll with the spaces. There
is no Pinned part while no tab of the page is pinned.
- **Pin.** Pin Tab under the pointer on a tab's capsule (before its ×) or in its context menu; Unpin Tab in the
  same places, and under the pointer on the pinned row (`pin.slash`, in the state icon's place) or in its menu.
- **Label.** "Pinned" (11 pt semibold, secondary), 8 pt into the rows, then the rows 2 pt apart, at most five
  (150 pt; more scroll inside), then a divider 8 pt in from the rows' edges.
- **Rows.** 28 pt, one line: the tab's program icons, its title (13 pt, the tab bar's title as plain text), its
  space's name (11 pt, secondary), and at the end the state icon of its strongest agent, none while idle.
  Pin order. Lit like the selected space row while it is the tab in view. A click shows the tab and gives its
  keyboard card the keys; rest the pointer to see its [hover card](#hover-card).
- **Kept** per machine and session, by herdr's tab id, across relaunches (`tabPins`). A tab moved to another
  space keeps its pin under its new id. A pin goes once a snapshot no longer has its tab.

## Space rows

One row per herdr space of the session, in herdr's order, like herdr's
Spaces panel.
- **Line 1.** The name (13 pt), 8 pt into the row, so the names, the branch
  lines and the page header's text start on one edge. So does the drag ghost
  "New Space". Nothing comes before the
  name. The name is medium weight while the row calls for the user (needs you
  or done).
- **Chevron.** A space that runs agents has a chevron (`chevron.right`, 10 pt semibold, secondary) at the end of
  the name's line, 8 pt in; it turns down while the row is unfolded. A click on it folds or unfolds the row's
  [agents](#agent-rows) and does not select the row; "Show Agents" or "Hide Agents" is its tooltip and VoiceOver
  label, "collapsed" or "expanded" its value. Rows are folded at first; each one's fold is kept per machine and
  session across relaunches (`agentsOpen`). The keycap hint and the rename field hide it. While the footer filter
  holds rows open, the chevron does nothing.
- **State icon.** At the end of the name's line, 8 pt in (6 pt before the chevron) and centered on
  that line: the state icon (12 pt, as a tab's) of the space's strongest agent, with no word and
  no time ([Status](/docs/ui/theme-and-accessibility#status)). An idle agent,
  or no agent, shows nothing. The keycap hint and the rename field take its
  place while they show. VoiceOver adds the state word to the row's value.
- **Line 2**, only for a git repository, under the name and starting where it starts: a branch glyph, the branch, then
  ↑ahead in the finished color and ↓behind in the error color when they are
  not zero. All 11 pt, secondary. There is no changed-file count. A space
  that is not a git repository has one line and no text about git (D67,
  [Git status](/docs/talking-to-herdr#git-status)).
- **Size.** 44 pt with two lines, 30 pt with one, 6 pt apart. The selected
  space is a raised pill (Liquid Glass in Glass), radius 10; unfolded, the pill covers its agents too. An unfolded
  row that is not selected has a 1 pt border (primary at 14 %) round it and its agents, and no glass.
- **Worktrees.** A space that herdr marks as a linked git worktree
  (`worktree.is_linked_worktree`) sits right after the space with the same
  `repo_key` that is not a linked worktree. It is indented 14 pt, with a 1 pt
  guide line in the separator color, 15 pt in, from under its repository's
  row (under its agents when unfolded) down.
  With no such space in the session, it is a normal row.
- **Keycap hints.** If the user holds ⌘ (with the tabs' keycaps) or ⌃⌘ for 0.7 s while the window is key,
  each of the first nine rows (in the order ⌃⌘1–9 jumps) shows a keycap
  "⌃⌘1"… at the end of its first line; the name
  gives way to it and never runs under it. Same look and fades as the tabs' keycaps.
- **Click** selects the space in the app only ([Selection and "seen" are
  the app's own](/docs/layout#selection-and-seen-are-the-apps-own)).
- **Context menu.** New Tab, Rename Space, Move Up, Move Down, Close
  Space. A row with a git line also has Fetch, Pull and Push, between
  separators before Close Space.
  - New Tab opens in the folder of that space's keyboard card, or `$HOME`.
  - Move Up and Move Down move a group past the next group. A group is a
    space and its worktrees. Both are disabled on a worktree row (it
    moves with its repository) and at the ends.
  - Fetch (`git fetch --all`), Pull (`git pull`) and Push (`git push`, which
    sets the upstream of a branch that has none) run in the folder of the
    row's git line, on the session's machine. git never asks for a password:
    it fails instead. While git runs, a [notice](#notice) with a spinner says
    "Pulling ‹name›…". When git ends, the git line is read again, and the
    notice turns to a green check and "Pulled ‹name›" for 2 s, or to git's own
    message in the error tone for 4 s. Pull and Push stay enabled at zero
    behind or ahead: the counts are from the last fetch, and Pull fetches
    first.
  - Close Space asks only when a program besides the shell runs in one of
    its panes, with what runs and the tab and pane count. On a repository
    with worktrees it also closes their spaces, and the dialog says so.
    The worktrees stay on disk.
- **Rename.** Rename Space, or a double-click on the name, puts a text
  field in its place: Enter saves, Esc cancels. An empty or unchanged name
  sends nothing.
- VoiceOver reads the branch with the ahead and behind counts, and "worktree
  of ‹repository›" for a worktree row.
- Drag a row to reorder the spaces
  ([Drag and drop](/docs/ui/drag-and-drop)).

## Agent rows

An unfolded [space row](#space-rows) lists its agent panes under its name, inside its glass or border,
4 pt in from its edges.
- **Order.** Newest change of state first (herdr's `state_change_seq`; herdr's order of tabs and panes among equals).
  While the pointer is over the space rows they hold still: a state, a time and a title change at once, and the
  rows move 1 s after the pointer leaves, sliding in 0.2 s (no motion with Reduce Motion). A new agent waits at the
  end until then.
- **One line**, 28 pt, one per agent pane, even when several share a tab: the program tile (8 pt into the
  space row, on the names' edge), then the pane's name (13 pt; its label, else its session's title, else its
  session's first typed prompt cut at 100 characters with "…", else "Untitled":
  [Session titles](/docs/ui/chat-view#session-titles)); the row's width cuts it further, and the
  [hover card](#hover-card) shows it whole. Then at the line's end the state box: the state icon (12 pt) in the
  state's color, on a 14 % tint of it with a 1 pt border at 45 % and 6 pt corners. Only a Working box adds a time
  after the icon: how long since the agent started working, 11 pt semibold in the state's color with tabular
  digits. It shows "&lt;1m" for the first minute, then "1m", "2m", … and "1h 5m", and changes once a minute. Needs
  you shows its icon alone; a finish the user has not seen shows the green check (the unread mark) until the user
  leaves that pane. An idle agent shows no box. The name is medium weight for needs you and an unseen finish.
- **Times.** herdr gives no times. The app records when it saw each agent's state change, with its
  `state_change_seq`, per machine and session, across relaunches: an agent whose number did not change keeps its
  time. An agent first seen after a launch counts from then.
- **Lit.** The row of the shown tab's keyboard card has a soft fill (primary at 8 %, 7 pt corners).
- A click goes to that space, tab and pane and gives the pane the keyboard. Its finish counts as seen when the
  user leaves the pane. Rest the pointer on a row to see the [hover card](#hover-card) of its tab.
- VoiceOver reads "‹name›, ‹space› · ‹tab title›" and the state word as the value.

How it works: [Agents and notifications](/docs/status#agents-and-notifications).

## Archived Sessions

A folded shelf at the sidebar's foot, above the footer: it stays there while the spaces scroll (D110). Settings ▸
Agents ▸ **Show closed sessions** (on by default) hides it, and then nothing is read.
- **The shelf.** A header 28 pt tall, 8 pt in: "Archived Sessions" (12 pt medium, secondary), then at its end a
  chevron that always shows: right while folded, down while open. Under the pointer it fills, as the header buttons
  do. A click folds or opens it; it is folded at first, and the fold is kept per machine and session across
  relaunches. Open, it is at most 5 rows tall (256 pt) and scrolls inside, with an 18 pt fade at an edge that has
  more rows; the spaces above get the rest. It has no count (it is not known without reading every store).
- **Filter.** At the header's end, before the chevron, a filter button (`line.3.horizontal.decrease.circle`,
  filled while it shows one agent, "Show Agent") opens a menu: **All Agents**, then the four agents. The choice is
  kept across relaunches.
- **Rows.** 48 pt, two lines, 3 pt apart: the agent's tile, the session's title, its folder on line 2 (`~` for
  the home folder), and its age at the end of line 1 ("5h", "2d", "1w"; 11 pt, secondary). Newest first, over the
  four agents. Left out: the sessions a pane of any open session of the machine runs, and one being resumed. The footer filter matches the title and the folder.
- **Reading.** The shelf reads each time it opens, 50 sessions an agent a page, and the next page
  when the list's end scrolls into view. One shell script an agent runs once a page on the machine
  (never a process per file), and nothing writes to the stores. Pi and Claude Code keep a JSONL file a
  session under `~/.pi/agent/sessions/` and `~/.claude/projects/`; the title is the last rename,
  else Claude Code's own title, else the first typed prompt. Codex and OpenCode keep an SQLite
  index, read with `sqlite3 -readonly`; without sqlite3 Codex reads its rollout files, and
  OpenCode's line says "OpenCode needs sqlite3 on ‹machine›." Left out: subagents and child sessions,
  `codex exec` runs and Claude Code's Agent SDK sessions, archived ones, and sessions with no prompt.
- **States** ([States](/docs/ui/states)). While a page takes over 0.3 s: the loader, "Reading sessions…". With no
  row, the compact empty state: "No closed sessions on ‹machine›." or "No ‹Agent› sessions." (`archivebox`), or "No
  matching sessions." (`magnifyingglass`). A machine that did not answer in 10 s: "Could not read ‹machine›'s
  sessions." (`exclamationmark.triangle`) with **Retry**; so does a store the machine cannot read ("OpenCode needs
  sqlite3 on ‹machine›.").
- **Resume.** A click, or the hover **Resume** (`arrow.uturn.backward`, before the age),
  starts the agent with that session (the flags of [Relaunch with
  Chat](/docs/ui/chat-view#relaunch-with-chat)'s table) in a new pane in the session's
  folder: a new tab after the selected tab of the space whose folder holds it (the deepest; a
  folder two levels deep or less, as `/` or `/Users/me`, holds only itself), else a new space
  there. ⌥-click, and the menu's **Resume to the Side**, split to the right of the keyboard card
  instead. The menu has **Resume** and **Resume to the Side**. A row resumes once: it
  leaves the shelf until its start ends. A folder that is gone says "‹folder› is gone" in a notice

## Open Session

The one place to create or open a session, as a page of this window (D68).
The footer's Open Session button, the
space menu's and the machine menu's "Open Session…" and File ▸ Open Session… (⌥⌘T) open it.
- A glass panel like the command palette, 420 pt wide, near the top of the
  window, with no title and no buttons: Enter acts, Esc or a click outside
  closes it. One panel shows at a time: opening it closes the command palette
  or the space menu, and opening one of those closes it.
- A text field, "Name a new session, or find one", empty and with the
  keyboard at first.
- The list, filtered by the field. It shows at once the sessions the page
  last read (as it connected, or as the panel last opened), then reads them
  again; a change updates its rows in place. It lists only the window's
  machine's sessions (the page's own store, one per machine and session).
  Groups with the headers "New", "Running", "Stopped" and "Open in this
  window"; in a remote window "Running on ‹machine›" and "Stopped on
  ‹machine›", as both machines often run the same names (`default`):
  - **New:** "Create session “‹typed name›”" when the text is a valid herdr
    session name that no session has. With an empty field: "Create session
    “‹name›”" with a suggested two-word name.
  - **Running** sessions that are not open in this window, then **Stopped**
    sessions.
  - Last, the sessions already open in this window.
  - The rows carry no hint text: the group headers say what a pick does. A
    small symbol leads each row: a plus to create, a stack for a running or
    stopped session, a checkmark for an open one.
- The arrows or the pointer move the highlight, in the same frame and with no
  fade, as in a menu (a row scrolled under a still pointer does not take it).
  Enter or a click acts on a row.
  - A new name, a running session and a stopped session take one path. The
    app starts the server if it is not running (a launchd job on This Mac,
    D47); a server the app started gets its first space in `$HOME`. Then
    the session's page opens last in the window's pages and shows, and its
    store connects.
  - An open session: its page shows.
- **Stop and Delete.** The highlighted row of a running session (not open in
  this window) has a Stop button at its right end: the server stops, and every
  program in it ends; its spaces and tabs stay for its next start. The

- **Detach.** The highlighted row of a session open in this window has a
  plain Detach button, as File ▸ Detach Session: its page leaves this window
  and the session keeps running, listed again under Running, and the light
  goes to the list's first row. Not on the window's last page.
- While a server starts, stops or is deleted, its row shows a spinner. A
  failure shows its text in the panel, with Retry, and the panel stays open.

## Tab page

- The window shows the selected tab's page, full width, and only it. A switch
  replaces it at once (D12).

  spaces, stay made under the shown one, hidden. A switch to one of them

- A pane the app creates shows the [New pane](/docs/ui/new-pane) chooser

- Inside a page, pane cards follow herdr's split tree, with an 8 pt gap

- Layout changes animate over 0.13 s: a new card slides in from its side, a
  closed one fades away, a zoom grows the card to the page and back. A

- Browser and plugin cards are made as their tab first shows

## Opening links and files

A link or a file opens the same way in every card that shows one: File
Explorer's tree and its Markdown, Git, the browser, the chat view and the
terminal.

| Gesture | Opens |
|---|---|
| a click | in the card, when the card shows that kind of place itself; else in a new tab, which is selected |
| ⌘-click | in a new tab, in the background |
| ⌥-click | in a pane to the side of the card, in the background |
| a right click | a menu of **Open**, **Open in New Tab** and **Open to the Side**, which do what the three gestures do |

- **What a card shows itself.** File Explorer shows files and folders (a
  file from its tree, a relative link in Markdown). Git shows its home and
  its diffs (a change, a commit, a parent). The browser shows web pages. So
  a web link in Markdown or in a chat reply, and a file from a Git diff, open
  in a new tab on a click.
- **HTML.** A link to an HTML file (`.html`, `.htm`) on This Mac, in the
  terminal or in Markdown, opens the file's page in a browser pane (a
  `file:` page). File Explorer's tree and a Git diff open the file as text,
  and a file card on HTML has **Open in Browser** (`globe`) in its header,
  which opens the page in a browser pane in a new tab, selected
  ([A file's row 2](/docs/plugins/default-plugins#a-files-row-2)). On a
  remote machine HTML opens as a file, since a remote card never shows a
  file over `file:`.
- **The look.** A link looks the same under the pointer with ⌘ or ⌥ down
  as with neither: in Markdown (locked, and unlocked off the caret's line)
  an underline and the pointing hand, in the browser the page's own look.
  The terminal, where only ⌘- and ⌥-click open a link, shows an underline
  and the pointing hand only while ⌘ or ⌥ is down, the same for either.
- **In the background** means that the selected tab and the keyboard stay
  where they are: a ⌘-click on one link after another opens each one. The
  menu's Open in New Tab and Open to the Side open in the background too.
- **A new tab** is in the card's space, on the same machine, also from a
  floating window ([New tabs](#tab-bar)). **To the side** is a split to the
  right of the card.
- **Lists select first.** In File Explorer's tree and Git's commit list a
  click selects a row and a double-click opens it (in the tree also ⌘O, in
  Git's list Return), as in the Finder. ⌘-click and ⌥-click open at once.
- **Markdown, unlocked,** opens a link on a click too, as locked, and
  shows it under the pointer the same way. On the caret's line a link shows
  its source, and a click there puts the caret in it. A Markdown link's
  menu ends with **Copy Link** (the file's path or the address).
- **The browser's menu** on a link is WebKit's **Open Link**, then **Open
  Link in New Tab** and **Open Link to the Side**. A `target=_blank` link
  opens a new tab in the background ([Popups, links and
  dialogs](/docs/ui/browser#popups-links-and-dialogs)).
- A link in a chat reply has no menu of its own: SwiftUI's text has none, so
  the right click shows the text's menu.
- A web page opened from Markdown or the chat follows the browser's load
  rule ([When a page loads by
  itself](/docs/ui/browser#when-a-page-loads-by-itself)). One opened from
  the browser is approved: the user picked it there.
- **A terminal's links** are the addresses and file paths libghostty finds
  in its text, and OSC 8 links. A terminal has no Open: a plain click is
  the program's. ⌘-click opens a link in a new tab and ⌥-click to the side,
  both in the background. An ⌥-click anywhere else is still the program's
  (a shell moves its cursor). The right click stays the card's menu, with no
  link items.
  - A link ends before the punctuation after it: `.`, `,`, `;`, `:`, `!`,
    `?`, and a closing bracket or quote it did not open.
  - A web address opens a browser pane. A file path (absolute, `file:`, `~`,
    or from the card's folder) opens only when a file or folder is there on
    the card's machine, so text that only looks like a path (`/reload your
    open pi`) opens nothing. libghostty still underlines it while ⌘ or ⌥ is
    down: the app cannot veto its highlight. A `file:` link, or an absolute
    or `~` path whose name has an extension (`~/notes.md`), names a file for
    sure: when it is gone, the click shows "File not found" instead. A
    `:line` after the path lands on that line. Other schemes (`ftp:`) open
    nothing.
  - Markdown opens in File Explorer's Markdown, HTML as above, other files
    with their default plugin.
  - libghostty underlines a link and reports it only while ⌘ is down, so the
    app gives libghostty ⌘ in ⌥'s place: with the pointer's moves while ⌥
    alone is down, and when ⌥ goes down or up with the pointer still (first
    off the view: libghostty looks again only on a new cell). A ⌥-click
    reads the link libghostty reports there the same way. On a remote
    machine a ⌥-click on any path is taken, and the open checks the path
    there. The card's accessibility title is the link under the pointer.
- A `mailto:` or an app's link in a page or a chat reply opens its app.
- **A file that is gone.** A click, ⌘-click, ⌥-click or menu item on a file
  or folder that is no longer there (a terminal link, a Markdown link, a Git
  diff's file, a row of File Explorer's tree, ⌘K's Open File, `ovvi open`
  typed in a shell) opens nothing and shows a [notice](#notice) in the
  warning tone: "File not found: ‹path›", with the home folder as `~`.

## Find bar

⌘F (Edit ▸ Find…) opens the find bar on the keyboard card; ⌘F again focuses
its field. It is disabled on a browser card and on a plugin card that shows
Preview or the Git home. On File and Markdown ⌘F, ⌘G and ⇧⌘G use the
editor's own search, and on the tree and a Git diff the page's filter
([File Explorer and Git](/docs/plugins/default-plugins#keys)).
- A glass capsule 320 pt wide and 32 pt tall at the card's top right, 8 pt in
  from its edge and 8 pt under the header: the field ("Find"), the match count
  ("3 of 12", in a fixed slot so the bar never changes width), ↑ (Find
  Previous), ↓ (Find Next) and × (22 pt buttons with 11 pt regular glyphs, as
  the card header's). One bar per window page, on the card it
  opened on.
- A new query selects the last match, nearest the bottom. ⌘G or Enter goes to
  the next match down, ⇧Enter or ↑ to the previous one up, round the ends. Esc
  or × closes the bar and gives the keyboard back to the card. As in Rex, Find
  Previous has no shortcut here: ⇧⌘G is Go to Directory.
- The text comes from herdr, read when the bar opens and again at the next
  step after Return was pressed in the pane, and the search is case blind.
  Each match scrolls herdr's viewport to it, with the match line centered.
  Closing the bar scrolls back to the bottom. herdr's viewport is shared, so a
  herdr TUI on the same pane scrolls too.
- The matches on the screen are highlighted: the selected one in the accent at
  0.45, the others at 0.2, placed from herdr's visible text after each scroll
  and again 0.3 s after the pane's frames stop (at most 1 s of waiting).
- The bar closes, and herdr scrolls back to the bottom, when its card leaves
  view (another tab, space or page, or another card zoomed) and when its
  page or window closes. A failed scroll shows a [notice](#notice).

How it works: [Scrolling, queries and links](/docs/talking-to-herdr#scrolling-queries-and-links).

## Zoom

- The zoom button, a double-click on the header, or ⇧⌘↩ zooms a card. It
  fills its tab's page, as if it were the only pane. Only the
  zoomed card resizes; the others stay, hidden, at their size.
- A zoomed card shows only two buttons: Restore (the accent at 0.6 on an
  accent circle at 0.07, as in Rex; no saturated blue) and Close.
- A split from the zoomed card restores the layout first, so the new pane
  shows. Moving the keyboard to a hidden card restores it too.

  the pane needs it.

## Overview

Every tab of the session at a glance, as pictures (D70): for watching many
agents at once.
- **Open and close.** The title-row button (`square.grid.2x2`, after the
  tab bar, before ⌘), View ▸ Show Overview, the palette, and ⌃⌘O toggle it;
  Esc and the title row's × leave it. Each window has its own; it does not come
  back after a relaunch.
- **What it hides.** The sidebar, the tab bar and every title-row button: the
  row keeps only the traffic lights and, at its end, one × (Close Overview,
  ⌃⌘O) that leaves the overview. ⌘K still works. The overview covers
  the window below the title row. It appears and goes at once, with no fade
  or zoom.
- **Canvas.** The session in view, scrolled vertically. ⌥ + swipe sideways,
  ⌥⌘[ ] and the palette step to the window's previous or next session, which
  the overview then shows; a sideways swipe alone goes nowhere. From the top:
  the session's title as the sidebar's
  page header has it (13 pt semibold; This Mac's name for `default`), then
  the session's spaces in the sidebar's order, 32 pt apart: each
  space's name (13 pt semibold, secondary), then its tabs as tiles in a
  grid, 2 to 4 a row (as many 340 pt tiles as fit), 16 pt apart. Wide
  margins all round: 8 % of the window's width
  left and right (at least 48 pt), 40 pt above and below, so the grid sits
  centered.
- **Tile.** One card per tab (the card's fill, rim and edge): at its top a 36 pt title row like a card
  header (the tab's icon stack, its title with the folder dimmed, and its state
  label), and under it, 8 pt in, a miniature of the page: the tab's cards in
  herdr's layout, at the page's real proportions (the tab's page as it
  shows when the overview closes), each card its fill and edge with its
  content's picture inside, at the place and size it has in the card (no
  header content: the tile's title row names the tab). The picture is the
  terminal's snapshot, or the card's last picture for any other card: a
  browser's page, a plugin's content, a chat (its kind's symbol until the
  card has a picture). A zoomed tab shows its
  zoomed card. A floated pane's card shows the float icon. The selected tab
  of each space has the keyboard card's look. On hover the title row
  shows × at its end (Close Tab, as the tab bar's ×: it asks only when a
  program runs).
- **Click.** A click on a tile selects its space and tab and leaves the
  overview: the tab's page shows at once. The sidebar and the title row stay
  laid out under the overview, hidden, and show with it, so they come at
  once in a big session too. Esc, the title row's × and ⌃⌘O leave the same
  way, on the selected tab. A notification or Dock click leaves it and shows
  its pane. Other keys
  and the palette act as usual and the overview stays: ⌘T adds a tile, a tab
  key moves the selected tile.
- **Keyboard.** While the overview is open no terminal has the keyboard (a
  terminal view in a miniature refuses it); Esc leaves, unless a panel (the
  palette, Keyboard Shortcuts) or a text field is open. Closing it gives the keyboard back to the
  tab's card.
- VoiceOver: each tile is a button named by its tab's title, after its
  space's name.

### How the miniatures draw

- The tiles draw pictures, not live views, so the overview costs the window almost nothing (D70).
- **Taken as the overview opens** for the cards in view: each terminal's snapshot and each web card's
  picture ([Pictures and switches](/docs/ui/browser#pictures-and-switches)). The other cards keep the
  picture from their last show. A chat's picture is taken as its card leaves view, from the window's
  layers at its place: the deepest layer that holds the chat's rows, under 1 ms, without the reply box
  (`cacheDisplay` drew SwiftUI's content blank, and the window's root layer took 120 ms).
- A terminal tile with no snapshot yet shows a spinner and streams until its terminal drew, then lets go
  and keeps its snapshot. At most 16 such cards (6 on a remote machine) and 400 MB of surfaces stream at
  once, only the tiles in view, once a scroll ends. Nothing turns live or lets go while the grid
  scrolls. These are not visits (D46). The terminals' snapshots are
  kept up to 100 MB.
- A web card's or a chat's tile shows its last picture, else its kind's symbol (`globe`,
  `bubble.left.and.bubble.right`). A tile makes no web view, proxy or transcript read, and takes no web
  view from its card (one that did drew blank as it went back).
- A tile's terminal that streams draws live, scaled by AppKit (a layer transform): libghostty keeps
  its size and grid, and herdr's PTY keeps the card's size. The tile takes the terminal's view from
  its card in the kept tab page under the overview and gives it back when the tile goes.
- Cost: a live card keeps its surface at full card size (its swap chain:
  [What streams](/docs/talking-to-herdr#what-streams)), which is why the cap is in megabytes. Tiles cannot
  get smaller surfaces: libghostty-spm takes its content scale only from the window.

## Floating pane

A pane can float in a small window of its own, above the main window or, kept
on top, above other apps (D50). herdr has no floating pane, so this is
Ovvi's own: the pane stays in its herdr tab, and other devices and herdr
clients see it there.
- **Float Pane** (the `pip.enter` button in the card header, the pane's menus,
  View ▸ Pane and the palette) opens the window. Several can be open. On a
  floated pane's card the button is lit, and it brings the window to the
  front.
- **The window** has no tab bar and no sidebar. Its title row is the main
  window's: 46 pt, with the traffic lights where the main window has them.
  It holds the traffic lights, then the pane's quick info, a thin vertical
  line, then the place, "session › space › tab", in 11 pt tertiary text,
  quieter than the pane's folder, on one line (the
  session as the sidebar names it, so `default` shows the machine's name; a
  long one gives way first, in its middle). The quick info is the pane's
  icon, its title and its agent's state label. The title is
  the program and folder or the label, an agent's name and its pane's name,
  "Browser" and the page, a plugin's name and title with its Edited dot, or "New Pane" while
  the chooser shows, with the second part in
  secondary text (the window's title has ` | ` there). A plugin pane (any
  `ovvi:` label, such as a browser) shows no line and no place. A chat pane
  shows Chat | TUI after the place. Then on the right the title
  row's 28 pt buttons: **Stay on Top** (a pin), **Close** (closes
  the pane, and asks first as any close does, in the floating window, also
  for a Close from the card in the tab) and, rightmost, **Detach**
  (`pip.exit`: the window closes and the card shows its terminal in its tab
  again; nothing stops). The red traffic light detaches too. Below the title
  row, the glass card holds only the terminal, with no header, 8 pt in from
  the window's edges, its text 10 pt in from the card's sides, as in a pane
  card. A chat pane's card shows its chat or its terminal
  ([Chat view](/docs/ui/chat-view#switching-views)), a browser pane's card
  its toolbar and page ([Browser](/docs/ui/browser#the-card)), a plugin
  pane's card its row 2 and page ([File Explorer and Git](/docs/plugins/default-plugins#the-card)),
  and a pane at
  the chooser the chooser. A browser's toolbar and a plugin's row 2 start
  4 pt below the card's top edge (only in a floating window), so their first button sits as far from the card's
  top edge as from its left, 11 pt. The window is at least 320 pt wide, and never
  narrower than its title row needs (a chat pane's switch makes it wider).
  A pane's first float opens it at 60 % of the main window's width and 75 %
  of its height (at least 720 × 460 pt), centered over the main window; it
  moves and resizes like any window, and keeps its frame for the next time
  that pane floats.
- **Stay on Top** keeps the window above every app's windows and on every
  macOS Space (Mission Control), like picture in picture. It stays on until turned off.
- **In the tab** the card keeps its place in the splits and its header. In
  place of the terminal, in the middle of the card: "This pane is open in a
  floating window." in secondary text, and under it two buttons side by
  side: **Show Window** brings the window to the front, **Bring Back Here**
  detaches the pane (as Detach: the window closes) and gives its card in the
  tab the keyboard. The placeholder is never the keyboard card: ⌘[ ⌘]
  and Focus Follows Mouse skip it.
- **Keys and ⌘K.** In the floating window the menu bar and the palette offer
  only what applies to it: Detach Pane (⌘W, as the red light: a window's
  close puts the pane back, nothing stops), Redraw Terminal (⌥⌘R), Replace Pane (⇧⌘R), Open Terminal
  Here, Start Agent Here, Open Browser Here, Open File Explorer Here, Open
  Git Here, Close Pane (⇧⌘W), Stay on Top, Find, Find Next and Find Previous, the
  font size items, Copy and Paste, on a browser pane Reload Page (⌘R), Open
  Location (⌘L) and Show Web Inspector (⌥⌘I), and on a File or Markdown pane
  Save (⌘S) and on a Markdown pane Lock Editing (⌘E). The palette lists no tabs, spaces or sessions.
- **Saved.** The floating panes and their Stay on Top are kept with the main
  window that floated them, and open again when it restores. A pane that
  herdr closed closes its window; one that moved to another tab or space
  stays floating (its terminal is the same), and the main window stays where
  it is. Closing the main window closes
  its floating windows.
- The terminal streams the whole time it floats, whichever tab or session the
  main window shows. Another window on the same session shows the pane as a
  normal card.
- **From other tools:** `ovvi://float?session=‹herdr session›&pane=‹pane id›`
  (and `&machine=‹machine id›` for a remote machine; This Mac otherwise)
  floats that pane over the machine's front main window, also when its
  session is not open there: then the session gets no page, no sidebar row
  and no page in view, and it disconnects when its last float goes (such a
  float does not come back after a relaunch). Open again for the same pane,
  it brings the window forward. A session or pane that is not there shows a
  notice and no window.
- **From a pane, on any machine:** `ovvi float <pane>`
  ([CLI](/docs/agent-control/cli#float-and-unfloat)), run in a pane of a
  session the app follows, floats the pane it names the same way, over the
  window where the user last typed or clicked in a card of that session.
  The window comes to the front without activating Ovvi, and the keyboard
  stays in the window that had it. A pane that floats already comes to the
  front. `--on-top` turns on Stay on Top, and `ovvi unfloat` detaches it.
  The app marks the panes it shows, so pi-herd asks it only for a click in
  one of them; herdr's own popups do not show in Ovvi. The older
  [float request](/docs/talking-to-herdr#float-requests) still works the
  same way.

## Notice

A short message after a failed action or a refused move, or from an agent.
- A capsule at the bottom center of the tab's page, 30 pt above its bottom, 36 pt
  tall: glass, a leading symbol in a tone color (red `xmark.octagon.fill` for
  an error, orange `exclamationmark.triangle.fill` for a warning, blue for
  information, a spinner while a command runs, a green
  `checkmark.circle.fill` when it ended), the text (two lines at most), an
  optional action button and ×.
- A failed write's notice has no action: after a timeout the write may have
  happened, so a retry is not safe. The Open Session panel's "Could not
  start" notice has **Retry**.
- **From an agent** ([Agent control](/docs/agent-control#the-users-view)):
  "‹agent› opened ‹Kind› ‹title›" for a card that `ovvi open` made out of
  view, and "‹agent› points to ‹title›" for `ovvi reveal` of a pane out of
  view or a card that `ovvi open` found already open. It is in the
  information tone, with **Show**, in each window that shows the session.
  Show selects the pane's space, tab and card in that window. Ovvi does
  not come to the front for it.
- It goes after 4 s (a check after 2 s; a spinner when its command ends), or
  at ×. A newer notice replaces it. After × or a newer notice, a command's
  check does not show; its error does.

## Control capsule

A window that watches a session another window controls (D66).
- Its cards of that session draw their content at 0.85 of its opacity, and a
  capsule at the bottom center of the tab's page, 30 pt above its bottom, says
  "Controlled in another window", with **Take Back**. It is a
  [notice](#notice) in the information tone with `macwindow.on.rectangle` and
  no ×, sits under a notice when both show, and shows only while the page in
  view is watched. VoiceOver reads its text when it appears.
- Take Back, or a key press, paste or click in one of its terminal cards,
  moves control of the session to this window. The other window then watches
  and shows the capsule.
- A pane that another device holds shows "In use elsewhere · Take Back" in its
  card instead
  ([One controller per pane](/docs/talking-to-herdr#one-controller-per-pane)).

## Command palette

⌘K or the title-bar ⌘ button opens it (D48). ⇧⌘P also opens it (Rex's key).
- 480 pt wide, with 10 pt around its content. The list is the exception at
  the bottom: it runs to the panel's bottom edge, so a row cut by the scroll
  is cut at that edge. Its 10 pt sit after the last row, and show only when
  the list is scrolled to its end. Open Session's list does the same with its
  8 pt. The search field says
  "Search", in 15 pt text with 12 pt of padding at its sides and 9 pt above
  and below. It is a rounded rectangle of the panel's radius, 14 pt. Its
  fill is flat white at 8 % in dark and black at 6 % in light, in both
  styles: the panel is the same glass in both.
- **Rows.** 32 pt: a symbol, the title, and on the right the shortcut, or ›
  for a row that opens a sub-page. The shortcut is one keycap per key (⇧, ⌘,
  W), the same caps as the tabs' ⌘1 hints. The selected row is an accent pill,
  radius 8; the arrows or the pointer move it. Only a pointer that moves
  moves it: rows that scroll under a still pointer leave it where it is.
- **Groups.** On the first page with an empty field, the rows sit in groups,
  each under a header, in this order: Tabs, Spaces, Sessions, Panes, View,
  Edit and Plugins. A group holds the commands that act on that thing. Tabs
  lists the selected space's tabs first, then the tab commands. Spaces
  lists the spaces of every page in the window, with the session's name,
  then the space commands. Sessions lists the pages open in this window,
  then the session commands; Open Session… opens the
  [Open Session](#open-session) panel. A group with no enabled command and no
  place does not show. A typed filter gives one list, best match first, and
  each row shows its group's name, dimmed, after its title. A sub-page shows
  only its own rows, under its title.
- **Matching.** Fuzzy, in the order of the typed letters, over titles and
  keywords: "split" finds Split Right, "dark" finds Appearance ▸ Dark. On a
  tie, the title that is the whole filter comes first ("open file" gives
  Open File › before Open File Explorer Here), then a title that starts with
  the filter ("font size" gives Font Size › before Increase Font Size), then
  commands before places, then the menu's and the sidebar's order.
- **Rows at open.** The palette reads its commands and places once, as it
  opens. A tab that changes its title while the palette is open keeps the
  old title in it, and a tab closed meanwhile stays listed and does nothing.
  Each typed key only filters these rows.
- **Sub-pages.** ⌫ on an empty field or Esc goes back one page; Esc on the
  first page closes the palette.
  - Rename Tab ›, Rename Space ›, Rename Pane ›: the field holds the
    current name; Enter saves.
  - Move Pane to Tab ›: New Tab, New Space, then the session's other tabs
    under their spaces' names. A move into a tab lands right of its last
    card.
  - Appearance › and Interface Style ›: a row highlighted for 0.75 s previews
    on the window. Enter keeps it; Esc restores the old one.
  - Font Size ›: 8 to 32 pt.
  - Start Agent Here ›: Claude Code, Codex, Pi and OpenCode
    ([New pane](/docs/ui/new-pane#commands-that-change-a-panes-kind)).
  - Open File ›: a field for a path. `~` is the home folder, and a
    relative path starts at the keyboard card's folder, on its machine.
    Enter opens the file or folder with its default plugin, as
    [`ovvi open ‹path›`](/docs/agent-control/cli#open) does, in a new tab;
    ⌥Enter opens it to the side. A path that names nothing gives a notice.
  - Open Commit ›: a field for a commit's hash or a ref (`main`,
    `HEAD~2`). Enter opens Git at that commit of the keyboard card's
    repository, as `ovvi open git . ‹commit›` does; ⌥Enter to the side.
- **Open Working Tree** opens Git at the uncommitted changes of the
  keyboard card's repository, in a new tab (⌥Enter: to the side).
- **A typed path.** On the first page, a filter that starts with `/`, `~`,
  `./` or `../` and names a file or folder on the page's machine gets the row
  **Open ‹path›** first. Enter opens it as Open File does; ⌥Enter to the
  side.
- **Go to Directory** (⇧⌘G, which is Find Previous over a File or Markdown
  card) opens the system folder panel at the keyboard
  card's folder. Choosing a folder types `cd -- '‹path›'` and Return into the
  card. Enabled only when the card runs only its shell.
- **Insert Path** (⇧⌘I) opens the same panel with files too. Choosing types
  the shell-quoted path at the cursor, without Return. On a remote machine the
  panel shows only This Mac's files: the chosen file is copied to the machine
  as a dropped file is ([Drag and drop](/docs/ui/drag-and-drop#files-and-images)),
  and the copy's path is typed.
- **Settings as commands.** Each on/off setting in the menu bar is one command
  whose title says what it does now: "Turn On Focus Follows Mouse" or "Turn
  Off Focus Follows Mouse".

The palette and the menu bar come from one command list, so each title and
shortcut is written once
([Keyboard shortcuts](/docs/ui/theme-and-accessibility#keyboard-shortcuts)).
