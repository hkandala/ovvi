A plugin's entry exports one function. Ovvi calls it with the `ovvi` object when the card's page loads. Everything
that the page asks of the app goes through that object. File Explorer and Git use this same API.

```ts
import type { Ovvi } from "@ovvi/plugin-api"

export default async function main(ovvi: Ovvi) {
  const { text } = await ovvi.files.read(ovvi.card.arg)
  document.body.textContent = text
}
```

- The card shows a loader until `main` returns, or until the page calls `ovvi.card.ready()`.
- If `main` throws an error, the card shows "‹name› stopped" with the message, and Reload.
- Ovvi starts a page's calls in the order that the page made them. Of two `controls.set` calls to one control, the
  second one wins.
- Every call works only on the card's own machine.

## Types

`@ovvi/plugin-api` is a package of types only. Ovvi gives the `ovvi` object to the page when it runs, so a plugin
never bundles it.

- List `@ovvi/plugin-api` in `peerDependencies` as `"*"`, and mark it `optional` in `peerDependenciesMeta`. The
  template does this.
- Ovvi writes the types to `~/.config/ovvi/plugins/node_modules/@ovvi/plugin-api/`. TypeScript finds them from any
  plugin in that folder, so `npm run check` works there.
- For a plugin in another folder, install the types: `npm install -D @ovvi/plugin-api`.
- Import with `import type`, so nothing of the package goes into the build.

The full types are at the end of this page ([All the types](#all-the-types)).

## The parts

| Part | What it does |
|---|---|
| `card` | Who the card is: its instance id ([Labels](#labels)), plugin, machine, place (`arg`), folder (`cwd`) and landing (`at`: the line or the diff file that a link opened to). `go` moves the card to another place, `ready` ends its loader, `setDirty` shows the Edited dot. |
| `files` | Reads, lists, writes, moves and watches files on the card's machine. |
| `git` | The repository's root, status, changes, branches, history, patches and commits, and the everyday writes: stage, unstage, revert, commit, fetch, pull, push, switch, init. |
| `run` | Runs a command on the card's machine: argv, no shell, 30 seconds unless `timeout` says otherwise, two at a time per card. |
| `state` | The card's own value, kept over reloads and relaunches ([State](#state)). |
| `controls` | Changes the header's controls and the card's commands ([Header](/docs/plugins/manifest#header)). |
| `theme` | The app's colors, light or dark, and text size ([Theme](#theme)). |
| `settings` | The values of the plugin's settings. `open` shows the plugin's page in Settings. |
| `pages` | Draws each place of the card in a page of its own ([One plugin, many places](#one-plugin-many-places)). |
| `open` | Opens a file, a folder, a URL or a plugin's argument: in this card, in a new tab (the default), in a pane at its side, or in the Mac's default app. |
| `toast` | One line at the top of the card, with up to two buttons. |
| `menu.show` | A native context menu at the pointer. |
| `pick.folder` | Choose Folder: the folder panel on This Mac, a folder field on a remote machine. |
| `symbol` | An SF Symbol as a PNG, to use as a mask. |
| `clipboard.write` | Puts text on the clipboard. |
| `on` | Gets events from the app: `control`, `place`, `save`, `find`, `findNext`, `findPrevious`, `visible`, `keyboard`, `theme` and `settings`. |

- `on` returns a function that stops the handler. Every handler and watch ends with the page, so a reload needs no
  cleanup code.
- Each `console` line and each uncaught error goes to the plugin's log
  ([The log](/docs/plugins/create#the-log)).

### Errors

A call that fails rejects with an `OvviError`. Its `code` says why:

| Code | Why |
|---|---|
| `notFound` | The file or folder is not there. |
| `notText` | The file is not UTF-8 text. |
| `tooLarge` | The file is over 16 MiB. |
| `changed` | The hash given to `files.write` differs: the file changed. |
| `timeout` | The call took too long. |
| `closed` | The card closed, or its plugin was removed. |
| `failed` | Anything else, with git's or the command's message. |

### Limits

| What | Limit |
|---|---|
| A file that `files.read` or `files.readBytes` reads | 16 MiB |
| A file that `files.read` gives as writable on a remote machine | 4 MiB |
| The output (stdout) of `run` | 4 MiB, then `truncated` is true |
| The error output (stderr) of `run` | the last 8 KiB |
| A card's state | 256 KiB of JSON |

## Keyboard

`ovvi.card.keyboard` is true while the card has the keyboard, and the `keyboard` event brings each change. When the
card gets the keyboard, the page gets its window's `focus` event: focus your own field then.

- Only the app gives a card the keyboard. While the card does not have it, an element's `focus()` does nothing.
  During a click in the page, `focus()` works.
- The app's menu keys go first. A plugin cannot take the app's ⌘ keys. Put the plugin's own keys in `commands`
  ([Commands](/docs/plugins/manifest#commands)).
- Keys that no menu item takes reach the page.

## Theme

Before the first paint, Ovvi sets the app's colors as CSS variables on the page's root element: `--text`, `--dim`,
`--divider`, `--card`, `--accent`, `--on-accent`, `--working`, `--needs-you`, `--finished` and `--error`. It also
sets `--app-text-size` and `color-scheme`. When the theme changes, Ovvi sets them again and sends the `theme`
event.

- Ovvi sets the root's inline style again with each theme. Put your page's own variables in a style sheet.
- The app's style sheet loads before the plugin's CSS. It sets system fonts at 13 px (`--font-size`), no margin
  and a clear background, so the card's fill shows behind the page.
- The class `ovvi-sidebar` makes a sidebar that slides in and out as the window's sidebar does. Put it on a flex
  child with `--sidebar-width`, and set the attribute `data-closed` to hide it. Give its parent `overflow: hidden`. The class `end` puts it on the right.
- When Animations is off in Settings ▸ Appearance, the root has the attribute `data-animations-off`, and the app's
  style sheet turns off every CSS transition. CSS animations, such as a spinner, keep going.

## Visible

A card is visible while it is in the shown tab or in a floating window. When it is not, it gets the `visible` event
with `false`, and its watches stop. Its `run` calls go on. When it shows again, each watch calls back once.

## One plugin, many places

One card can show several places. For example, File Explorer shows a folder's tree, a file and a preview, and Git
shows its home and a diff. The plugin draws every place itself:

- `ovvi.card.go(arg, { at })` moves the card to a new place. The pane follows, so a reload comes back there. The
  page does not load again. If the card has unsaved edits, Ovvi asks first.
- With `"history": true` in the manifest, Ovvi keeps Back and Forward for the card and shows them in its header.
- The `place` event fires on every move: the page's own `card.go`, Back, Forward, or a new argument from elsewhere
  (such as an agent). After Back, `at` is the place it came back from, so a tree can select the file it opened.
- When `document.title` is not empty, it is the card's title. A place with no title of its own sets it back to "".
- `ovvi.pages.route(draw)` draws each place in a page of its own. The card keeps the last five pages, hidden, so
  Back and Forward show a page at once, with its scroll and its selection. The page before stays on screen until a
  new page has drawn. With `pages.route`, the app's Back and Forward keys work too.
- Each page has its own `ovvi` (`page.ovvi`). Its handlers run only while the page shows, except `theme`, `visible`
  and `settings`. Its watches call back only while it shows, and once when it shows again. Its header controls come
  back as the page left them.
- A page left with unsaved edits is dropped. `page.redraw()` draws the shown place again in a new page.
- Load a heavy place with a dynamic `import()`, so a simple place loads fast. A bundler links no CSS for a dynamic
  chunk, so import all the CSS from the entry.

## State

Each card has one state value, which the plugin sets with `ovvi.state.set` and reads with `ovvi.state.get`. Use it
for what you want back after a reload: the sort, the selected row, a draft. Put data that other devices must see in
files on the machine.

- Ovvi keeps the value at once, with the values of the header's controls. A reload gives the page the same value.
- 500 ms after the last change, Ovvi writes both to a file on the card's machine:
  `~/.local/state/ovvi/<session>/<plugin-id>/<instance id>.json`. So a relaunch, another device, or a restart of
  herdr starts where the card was.
- The state holds at most 256 KiB. Ovvi does not keep a larger value, and the log shows the error.
- The last write wins. Closing the pane removes the file. Ovvi deletes a state file that nothing wrote for 30 days.

```json
{ "controls": { "diff.layout": "split" }, "state": { "draft": "Fix the login", "list": false } }
```

## Labels

herdr keeps each plugin card as a pane with a label. The label names the plugin, the card's instance id and its
argument:

```text
ovvi:<plugin id>#<instance id> <argument>
ovvi:csv-table#k3f9q2 /Users/me/data.csv
```

- The instance id is exactly 6 characters of `a-z` and `0-9`. If a label that you write by hand has another id, the
  pane stays a terminal, with no error.
- The argument is at most 1024 characters.
- The pane runs a small placeholder program, which shows "‹name› shown in Ovvi" in herdr's own interface
  (for example "Browser shown in Ovvi").
- To open a card from a pane, use `ovvi open <plugin id> <argument>`
  ([The ovvi command](/docs/reference/ovvi-command#open)). It writes the label for you.

## Versions

- The manifest's `api` is the API version that the plugin is written for. This page is version 3, and Ovvi gives
  version 3.
- The number goes up when a plugin written for it fails on an older Ovvi, as with a new call. A new event,
  manifest field or control field keeps the number: an older Ovvi ignores what it does not know.
- Ovvi runs a plugin whose `api` is at most its own. It refuses to install a newer one, and the card of a newer one
  shows "‹name› needs a newer Ovvi".
- Only the `ovvi` object is the API. The messages between the page and the app are not.
