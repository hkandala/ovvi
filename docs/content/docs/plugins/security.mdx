A plugin is code that you, or an agent of yours, installed. Ovvi does not put a plugin in a sandbox. It asks you
once before a plugin's code first runs, and it keeps the content that a card shows from taking over the card.

## What a plugin can do

A plugin can do what you can do, on this Mac and on each machine where you open one of its cards:

- Read, write and move any file that you can.
- Run any command as you with `run`, also one that uses the network, and run git.
- Write to the clipboard.
- Run its package's `build` script as you on this Mac, when Ovvi builds it.

The manifest lists no permissions. A plugin that can run a command can do anything else too, so Ovvi cannot
keep a list of permissions. Install plugins only from sources that you trust.

## The confirmation

The default plugins never ask. Any other plugin asks once, before its code or its build script first runs:

| How the plugin comes | When it asks | Where |
|---|---|---|
| An install from npm or git | before its dependencies install | a dialog, with Install and Cancel |
| A folder that you add on the Plugins page | when you add it | the same dialog |
| An agent's `ovvi plugins install` | as for an install from the Plugins page | the same dialog, in the window of the agent's session |
| New Plugin…, or an agent's `ovvi plugins new` | never: you or your agent made it | |
| A folder put in the plugins folder by hand, or a path written in `settings.json` | at its first card | in the card |

The confirmation shows:

> Install “CSV Table”?
>
> `csv-table 0.1.0 from npm:csv-table in ~/.config/ovvi/plugins/csv-table`
>
> A CSV or TSV file as a table you can sort.
>
> Plugins run code as you on this Mac and on the machines whose cards you open, including their build script.
> Install plugins only from sources you trust.

- The id, the version, the source and the folder come first, because a plugin picks its own name.
- A plugin with `connect` in its manifest adds a line, such as "Its page connects to ws://127.0.0.1:57900."
- A plugin with a row in New Pane adds a Show in New Pane checkbox, which is off at first.
- Install keeps the plugin's id in `~/.config/ovvi/trust.json`, and the plugin's waiting cards load. Cancel stops
  the install, or closes the card's pane.
- Ovvi removes control characters and direction-override characters from the text of the manifest.

A change to the plugin's code does not ask again. An update runs the new version with no question, unless the new
version has another id. When you confirm a plugin, you trust its source with its later versions too. Remove takes
the id out of `trust.json`, so the plugin asks again if you add it again.

### An agent's install

When an agent runs `ovvi plugins install`, the dialog starts with one more line: "‹agent› in pane ‹pane› asks to
install it."

- The dialog shows on the window of the agent's session. Ovvi does not come to the front: it bounces in the Dock.
- Return does not press Install, so keys that you type for another window cannot install a plugin. You must click
  it.
- Cancel answers the agent with `declined`.
- The command works only from a pane on This Mac.

## What Ovvi protects

A card often shows content that the plugin did not write: a Markdown file, a diff, a command's output. These rules
keep that content from taking over the card and its `ovvi` object:

- The page loads only its own files. Ovvi serves `ovvi-plugin://<id>/` from the folder of the plugin's entry: no
  subfolders and no hidden files. Each answer has this Content Security Policy:

  ```text
  default-src 'none'; script-src ovvi-plugin://<id> 'wasm-unsafe-eval';
  style-src ovvi-plugin://<id> 'unsafe-inline'; img-src ovvi-plugin://<id> data: blob:;
  media-src blob:; font-src ovvi-plugin://<id> data:; connect-src ovvi-plugin://<id> <connect>;
  frame-src 'none'; form-action 'none'; base-uri 'none'
  ```

  So no inline script and no `eval` run. WebAssembly runs. `fetch` and WebSockets reach only the plugin's own files
  and its `connect` servers on this Mac. The page has no other network access.
- The card stays on its own page. A link, a refresh or a form in shown content cannot take the page to another
  site. A plugin opens links with `ovvi.open`, which opens them in a browser card.
- Each card reaches only its own machine. Its `ovvi` object is tied to the card's machine, session and plugin when
  the card opens. Each card runs in its own process, and each plugin has its own web storage.
- `run` has no shell. It takes argv, and the card's argument is never part of a command line.
- Installs run no scripts of the package's dependencies.

Your plugin must put text from files and commands in with `textContent`, or the text API of its library, not as
HTML.

## What Ovvi cannot protect

- A plugin that you installed. Its code runs as you. Only the source that you install from protects you.
- A plugin's own mistakes. A plugin that builds HTML from a file's text, or passes a file's words to `run`, can be
  used by that file. The Content Security Policy limits the first. Nothing in Ovvi limits the second.
- A machine's own processes. Any process on a machine can open a card of a plugin that you confirmed on that
  machine, as `ovvi open` does. That gives it what the plugin does there. It cannot open a card on another machine.
