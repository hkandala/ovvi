---
title: "The manifest"
description: "The ovvi key of a plugin's package.json, field by field: what it opens, how it shows, its header, its commands and its settings"
---

A plugin's manifest is the `ovvi` key of its `package.json`. Ovvi reads it before any of the plugin's code runs. So
New Pane, the command palette, Open With and the card's header show at once, and the page only fills them in.

## An example

```json
{
  "name": "csv-table",
  "version": "0.1.0",
  "description": "A CSV or TSV file as a table you can sort.",
  "ovvi": {
    "id": "csv-table",
    "name": "CSV Table",
    "api": 3,
    "entry": "dist/main.js",
    "icon": "tablecells",
    "opens": { "files": ["*.csv", "*.tsv", "public.comma-separated-values-text"] },
    "header": [
      { "id": "rows", "type": "text", "style": "dim" },
      { "type": "spacer" },
      { "id": "first-row", "type": "toggle", "symbol": "tablecells.badge.ellipsis",
        "title": "First Row Is Header", "value": true },
      { "id": "reload", "type": "button", "symbol": "arrow.clockwise", "title": "Reload" }
    ]
  }
}
```

## Fields

From the package itself:

| Field | Required | Value |
|---|---|---|
| `version` | yes | The plugin's version. It shows on the Plugins page and in the confirmation. |
| `description` | no | One line. It shows in New Pane and in the confirmation. |
| `keywords` | no | With `chooser`: more words for the command palette to find Open ‹chooser›. |

In the `ovvi` key:

| Field | Required | Value |
|---|---|---|
| `id` | yes | 1 to 64 characters of `a-z`, `0-9` and `-`, which start with a letter or a digit. It is separate from the package name, which can have a scope (`@ovvi/git`). Two plugins cannot have the same id. |
| `name` | yes | The name that you read: in the card's title ("CSV Table data.csv"), Open With, the command palette and the Plugins page. |
| `api` | yes | The version of the plugin API that the plugin is written for, an integer, 1 or more ([Versions](/docs/plugins/api#versions)). |
| `entry` | yes | The built entry, a `.js` file in the package, such as `dist/main.js`. Its chunks, its CSS and its assets go in the same folder. |
| `icon` | yes | An SF Symbol name, or one of the app's own symbols, `source.branch` or `text.wrap`. It shows on the card, the tab and New Pane. |
| `opens` | no | What the card shows ([What a plugin opens](#what-a-plugin-opens)). With no `opens`, the card uses the pane's folder. |
| `chooser` | no | The plugin's row title in New Pane, and the command "Open ‹chooser› Here" ("Open ‹chooser›" in the command palette) ([How it shows](#how-it-shows)). |
| `header` | no | The controls of the card's header ([Header](#header)). |
| `history` | no | `true` shows Back and Forward at the start of the header, for the places the card went to ([One plugin, many places](/docs/plugins/api#one-plugin-many-places)). |
| `commands` | no | The card's commands in the menu bar and the command palette, with keys ([Commands](#commands)). |
| `handles` | no | The app commands that the card takes: `save` (Save, ⌘S) and `find` (Find, ⌘F, ⌘G, ⇧⌘G). |
| `settings` | no | Values that you set on the plugin's page in Settings ([Settings](#settings)). |
| `connect` | no | Servers on This Mac that the page can reach with `fetch` or a WebSocket. Each is an origin with `http` or `ws`, the host `127.0.0.1` and a port, such as `"ws://127.0.0.1:57900"`. The confirmation names them. |

- Ovvi ignores a field that it does not know, so a manifest written for a newer Ovvi still loads.
- If a required field is missing or a value is wrong, Ovvi does not load the plugin. The plugin's log and its cards
  name the field, such as `ovvi.entry must be a built .js file in the package` or `ovvi.header.1 has the wrong
  type` ([Errors and logs](/docs/plugins/create#errors-and-logs)).

## What a plugin opens

`opens` has one or more of these keys, and `priority`. The key sets what the card gets as its argument
(`ovvi.card.arg`), and the card's title.

| Key | The argument | The title | Example |
|---|---|---|---|
| `files` | a file's absolute path | the file's name | `{ "files": ["*.csv", "public.comma-separated-values-text"] }` |
| `folders` | a folder's path, which ends in `/`: the root of its git repository, else the folder | the folder's name | `{ "folders": true }` |
| `git` | a repository's root with its `/`, then optionally a space and `uncommitted` or a commit hash | the root's name, Working Tree or the short hash | `{ "git": true }` |
| `urls` | a URL | its last part | `{ "urls": ["https://github.com/*/*/pull/*"] }` |

- `files` is a list of patterns. A pattern is a file name glob (`*.csv`, `Makefile`), with no difference between
  upper and lower case, or a uniform type identifier (`public.image`). A type also matches its subtypes. A file
  type that macOS does not know (such as `.rs`) matches only a glob or `*`.
- `files` and `folders` can go together. File Explorer has `{ "folders": true, "files": ["*"] }`.
- `urls` is a list of globs for web addresses, with no difference between upper and lower case. In these globs, `*`
  also matches `/`. A web address that a plugin's `urls` match opens in that plugin, else in the browser.
- `priority` is `"default"` (the default) or `"option"`. An `option` plugin opens a file only when you pick it in
  Open With.
- Copy Address (⇧⌘C) copies the argument.
- A page's `document.title`, when it is not empty, replaces the title from the argument.

### Which plugin opens a file

A link in a card, a double-click in File Explorer and `ovvi.open` with no `plugin` open a file in its default
plugin. Ovvi picks it by the file's name alone, so it does not read a remote file first:

1. Only plugins with the `default` priority whose patterns match take part.
2. The most specific pattern wins: an exact name (`Makefile`), then a glob (`*.md`), then a type (a subtype before
   its supertype), then `*`.
3. On a tie, your plugin wins over a default plugin. Then the lower id in alphabetical order wins.

File Explorer's `*` has the lowest rank. So a plugin with `*.csv` takes `.csv` files from File Explorer. A path that
ends in `/` opens in the first plugin with `folders`.

## How it shows

| Place | What shows | From |
|---|---|---|
| New Pane | a row with the icon, the `chooser` title and the `description` | `chooser` |
| The File menu, the card's menu | "Open ‹chooser› Here" | `chooser` |
| The command palette | "Open ‹chooser›" | `chooser`, `keywords` |
| Open With (an `openWith` control in the header) | after the Mac's apps, every other plugin whose patterns match the file, `option` ones too. A pick turns the card into that plugin's card (a new pane in its place) | `opens.files` |
| The card's title, the tab, a floating window | "‹name› ‹title›" and the icon | `name`, `icon`, `opens` |
| The pane in herdr's own interface | "‹name› shown in Ovvi" | `name` |
| Settings ▸ Plugins and the plugin's page | the icon, the name, the version, the description and the settings | `icon`, `name`, `version`, `description`, `settings` |

- `chooser` works only with `folders`, `git` or no `opens`: a new pane has a folder, not a file or an address.
- Open With lists the Mac's apps only for a file on This Mac. It lists the plugins on every machine.

## Header

`header` lists the controls of the card's header, from left to right. Ovvi draws them as native controls. They
show before the page loads, in a pane and in a floating window. The page changes them with `ovvi.controls.set`
and gets their changes with `ovvi.on("control")` ([The plugin API](/docs/plugins/api)).

| `type` | Fields | What it is | What the page gets |
|---|---|---|---|
| `button` | `id`, `symbol`, `title`, `badge`, `busy`, `label`, `style` | an icon button. `title` is its tooltip. `badge` shows a count after the symbol. `busy` shows a spinner. With `"style": "bordered"`, a small bordered button with the symbol and the title | `{ id }` on a click |
| `toggle` | `id`, `symbol`, `title`, `value` (true or false), `onSymbol`, `style` | an icon button, in the accent color while on. With `onSymbol`, that symbol while on. With `"style": "segment"`, a segment of a pill | `{ id, value }` |
| `segmented` | `id`, `options` (`[{ "value", "title", "symbol" }]`), `value` | segments in a pill. An option with a `symbol` shows only the symbol, with the title as its tooltip | `{ id, value }` |
| `menu` | `id`, `title`, `symbol`, `items`, `value`, `busy`, `style` | a menu button that shows the picked item, else `title` and `symbol`. `"style": "icon"` shows only the symbol. `"style": "bordered"` draws a bordered button. An item is `{ "value", "title", "symbol" }`, `{ "title" }` for a section heading, or `"-"` for a divider | `{ id, value }` on a pick |
| `field` | `id`, `placeholder`, `value` | a search field that takes the free width | `{ id, value }` on each change, and `{ id, value, submit: true }` on Return |
| `field` with `"style": "path"` | `id`, `symbol`, `label`, `value` (a folder's path) | a path field. It shows the path with the home folder as `~`, and the whole path to edit when you click it. Esc puts the path back. `symbol` is a button before the path | `{ id, value, submit: true }` on Return, with the typed path made absolute, and `{ id }` on a click of the symbol |
| `text` | `id`, `value`, `style` (`plain`, `dim` or `path`), `symbol`, `digits`, `links` | text, cut in the middle when it is long. `path` shows a list of parts with `›` between them. `symbol` shows before the last part. `links` makes the first parts of a path buttons | `{ id, part }` on a click of a linked part, with the part's index from 0 |
| `openWith` | `id`, `value` (a file's path) | Open With: the default app opens the file, and its menu lists the other apps and the plugins | nothing |
| `spacer` | none | free space | nothing |

- Every control also takes `hidden`, `enabled`, `label` and `gap`. `label` is what VoiceOver reads when the title
  says too little ("Push, 1 ahead").
- `gap` sets the space before a control, in points. `0` joins icon buttons into a group.
- A `text` with `"digits": "mono"` has digits of one width, so a count keeps its width as it changes.
- Free space goes to a `spacer` or a `field`. With neither, it goes after the last control.
- Each control's `id` is unique in the plugin.
- A toggle's value is true or false, a `path` text's value is a list of strings, and other values are strings. Ovvi
  keeps the values with the card's state, so a card that loads again gets the same values.
- A toggle, segments and a field change their value themselves, then the page gets the change. A menu pick only
  sends the pick: the page sets the menu's value.
- `ovvi.controls.set(id, { focus: true })` gives a search field the keyboard. `ovvi.controls.set(id, { refused: true
  })` shakes a path field, which keeps the typed path.
- If only some places of a card use a control, give it `"hidden": true` in the manifest. The page shows its place's
  controls before it calls `ovvi.card.ready()`.
- A plugin with no `header` and no `history` has a header of one row.

## Commands

`commands` puts a card's commands in the menu bar and the command palette, with their keys. They are there only
while that card has the keyboard. Each command is also a row in Settings ▸ Shortcuts, in a group with the plugin's
name, where you can change its keys ([Shortcuts](/docs/reference/shortcuts)). The page never reads the key itself:
it gets the pick.

```json
"commands": [
  { "id": "lock-editing", "title": "Lock Editing", "menu": "view", "key": "cmd+e", "symbol": "lock",
    "keywords": ["markdown", "read", "edit", "unlock"] }
]
```

| Field | Required | Value |
|---|---|---|
| `id` | yes | Unique among the commands and the header's controls. |
| `title` | yes | The command's name in the menu and the command palette. |
| `menu` | no | `file`, `edit` or `view`: the menu that shows the command. The default is `view`. |
| `key` | no | The default key: `cmd`, `ctrl` or `option` (`alt`), with `shift` if needed, and one key. The key is a character or `left`, `right`, `up`, `down`, `return`, `tab`, `space`, `escape`, `delete`, `plus`. Examples: `cmd+e`, `cmd+shift+k`, `ctrl+option+left`. |
| `symbol` | no | An SF Symbol for the menu item. |
| `checked` | no | `true` shows a checkmark. |
| `keywords` | no | More words for the command palette to find the command. |

- A pick sends `{ id }` to `ovvi.on("control")`, as a header button does. `ovvi.controls.set` changes a command's
  `title`, `checked` and `enabled`. A disabled command has no key.
- Your own key in Settings wins over the default key. If an app command already has the default key, Ovvi leaves
  the key off, and the log says so.
- `handles: ["save"]` gives the card ⌘S. `handles: ["find"]` gives it ⌘F, ⌘G and ⇧⌘G. The page gets the events
  `save`, `find`, `findNext` and `findPrevious`.

## Settings

`settings` lists up to 16 values that you set on the plugin's page in Settings ▸ Plugins. Ovvi draws them from the
manifest, saves them in `settings.json` ([Plugin settings](/docs/plugins/install#plugin-settings)), and gives them
to the plugin's cards. `ovvi.settings.get` reads one, and the `settings` event brings each change at once.

```json
"settings": [
  { "id": "first-row", "type": "toggle", "title": "First row is the header", "default": true },
  { "id": "delimiter", "type": "choice", "title": "Delimiter", "default": "auto",
    "options": [{ "value": "auto", "title": "Auto" }, { "value": "comma", "title": "Comma" },
      { "value": "tab", "title": "Tab" }] },
  { "id": "rows", "type": "number", "title": "Rows to read", "default": 10000,
    "min": 1000, "max": 100000, "step": 1000, "description": "Larger files open the first rows only." }
]
```

Every setting has these fields:

| Field | Required | Value |
|---|---|---|
| `id` | yes | 1 to 64 characters of `a-z`, `0-9` and `-`, which start with a letter or a digit. Unique in the plugin. |
| `type` | yes | `toggle`, `choice`, `number`, `text` or `path` (the next table). |
| `title` | yes | 1 to 60 characters: the row's title. |
| `default` | yes | The value until you set one. It must fit the type. |
| `description` | no | One line under the title, up to 200 characters. |
| `section` | no | Up to 60 characters: a heading over this row and the rows after it. The first rows go under "Settings". |

| Type | Value | More fields | Shows as |
|---|---|---|---|
| `toggle` | `true` or `false` | none | a switch |
| `choice` | the `value` of one option | `options`: 2 to 12 of `{ "value", "title" }`, each value once | segments for up to 4 options whose titles have 24 characters in all, else a pop-up menu |
| `number` | a number | `min`, `max`, `step`, `unit`, all optional. `min` must be under `max`, and `step` over 0 | a field with a stepper, held in the range |
| `text` | a string of up to 1 KB | `placeholder` | a text field, saved on Return or when it loses the keyboard |
| `path` | an absolute path (it starts with `/` or `~/`, or is `~`), or empty | `kind` (`file` or `folder`), `placeholder` | a path field |

- There is no secret type. A plugin cannot ask for a password or a token in Settings.
- A wrong setting stops the plugin from loading, as a wrong header does. The log names the field, such as
  `ovvi.settings.2.default does not fit the type, options or range`.
- The page reads settings and never sets them. A card keeps its own choices in `ovvi.state`. A good pattern:
  `ovvi.state.get()?.layout ?? ovvi.settings.get("layout")`, so the setting starts new cards and a card's own choice
  wins.
